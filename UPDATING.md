# Как обновляется это портфолио

Короткая версия: **источник истины — закрытая монорепа
`industrial-automation-course`; сюда попадает не новый код, а новая
находка.** Единица обновления — кейс: реальный баг с железа, измерение с
числом, архитектурное решение с ценой ошибки. Коммит без находки сюда не
нужен.

## Что откуда

| Здесь | Откуда | Кто владеет |
|---|---|---|
| `case-*/safety_watchdog.py`, `case-*/pid_controller.py` | `weeks/…/src/…` — 1:1, см. [`.portfolio/manifest.yaml`](.portfolio/manifest.yaml) | источник; здесь не править |
| `case-*/README.md`, `case-*/test_*.py` | написаны для портфолио | портфолио |
| `README.md`, `LICENSE`, `.github/`, `UPDATING.md` | — | портфолио |

Если модуль нужно поправить — правка делается в источнике, потом `sync`.
Иначе через два месяца витрина и курс молча разойдутся.

## Триггеры обновления

- Прогон на реальном железе (Jetson, ПЛК, манипулятор) дал находку —
  запись в `docs/run-issues-log.md` источника со статусом 🔴→🟢.
- Пилот на реальной площадке дал измерение (латентность, память, брак).
- Исправлен модуль, который здесь зеркалится.

Каденция без триггеров — раз в месяц прогнать `check`, чтобы убедиться,
что дрейфа нет. Пустых «обновил README» коммитов не делать.

## Процедура (10 минут, если находка уже описана в источнике)

```bash
# 0. Источник лежит рядом (../industrial-automation-course) или задан
#    PORTFOLIO_SOURCE=/path/to/industrial-automation-course
python .portfolio/sync.py check          # 1. что изменилось в зеркалируемых модулях
python .portfolio/sync.py apply          # 2. скопировать (остановится на ценах/контактах/именах заказчиков)
python .portfolio/sync.py verify         # 3. тесты — то же, что CI
# 4. Новый кейс — по шаблону ниже. Старый кейс — обновить числа в README.
# 5. git commit: заголовок = находка одной строкой (см. ниже). Push. Бейдж CI зелёный.
```

## Шаблон кейса `case-N-<slug>/README.md`

Структура уже выработана в кейсах 1–3; новый кейс делается по ней, не
придумывается заново:

```
# Кейс N: <что произошло — одной строкой, без маркетинга>

## Задача / Контекст
Линия, железо, режим. Что ожидалось от симулятора, что случилось на железе.

## Диагноз  (для бага)   |   ## Архитектурное решение  (для решения)
Первая гипотеза и почему она не подтвердилась — тоже сюда, это часть истории.
Причина, а не симптом.

## Исправление / Критерий приёмки
Код — ссылка на модуль (полный, самодостаточный, без зависимостей от курса).
Критерий приёмки — ЧИСЛОМ: запас по времени, память, число тактов, 12→12 без дублей.

## Мой вклад в этот кейс
Что спроектировал/решил сам · что нашёл при ревью · что сгенерировано
с Claude Code по требованиям · что готов разобрать вживую без подготовки.
```

Правила отбора:
- Модуль **самодостаточен**: stdlib или одна-две зависимости, без импортов
  из курса. Если тянет полкурса — это не кейс, а пакет; ему место в
  `industrial-ai-portfolio`.
- У кейса есть **тест, закрепляющий число** из README (`test_*.py` рядом).
  CI гоняет его на Python 3.10 (JetPack 6) и 3.12.
- Нет имён заказчиков, площадок, цен, брендов. Манифест это проверяет
  regex'ом, но regex — страховка, не замена чтению глазами.

## Очередь кандидатов (из `docs/run-issues-log.md` источника, на 03.11.2026)

Все четыре — найденные и исправленные баги с числами, не гипотезы:

1. **Неделя 22, ERP-интеграция** — percent-encoding кириллицы в пути:
   баг, пойманный только на настоящем `http.server`, не на моке. Критерий
   приёмки: 12 событий во время сбоя ERP → ровно 12 уникальных после
   восстановления, буфер пуст. *Самодостаточный модуль буферизации +
   тест на сбой — идеальный формат кейса.*
2. **Неделя 21, безопасность OT-сети** — критерий приёмки зависел от
   скрытого порядка запуска (заранее сгенерированный `cert.pem`);
   принцип «критерий приёмки не должен зависеть от того, что запускали
   до него». Предупреждение `asyncua` реально воспроизведено без `--tls`
   и снято с `--tls`.
3. **Неделя 11, микросервисы на Jetson** — четыре бага за один прогон,
   из них один архитектурный: `week_loader` подменяет `sys.path`, но не
   переключает интерпретатор на чужой venv — заблуждение, записанное в
   трёх файлах комментариями. Плюс повтор бага «камера без `open()`» из
   кейса 2 — хороший повод показать, как одна причина всплывает дважды.
4. **Неделя 10, MQTT/OPC UA шлюз** — буферизация при недоступном
   брокере вместо падения; путь подтверждён `mosquitto_sub` на реальном
   топике UNS. *Это — первый кейс именно про АСУ ТП-интеграцию, а не про
   CV.*

Отдельная линия, **не из этой монорепы**: обезличенный фрагмент
документации ГОСТ 34 / KKS-утилита из Pipeline/RIGEL. Для неё в манифест
добавляется второй источник — это и будет первым кейсом, где видны 15 лет
АСУ ТП, а не годовой AI-эксперимент.

## Что сюда не попадает никогда

Полный курс, недели целиком, Docker-окружения недель, материалы пилотов,
имена площадок и заказчиков, цены, маркетинг, бренд. Портфолио — три
точки, которые можно разобрать вживую, а не копия продукта.
