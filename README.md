> *EN: Three hardware-proven cases — inference watchdog with a measured
> 282 ms margin at p99, a real camera-lifecycle bug and its root cause,
> an anti-windup PID with a counter-intuitive fact about the D-term.
> Each claim is pinned by a test that runs in CI.*

Три самостоятельных технических кейса из более крупного проекта
(24-недельный курс промышленной автоматизации с реальным Jetson Orin
Nano, ПЛК, камерой и манипулятором). Здесь — не весь проект, а три
точки, которые можно разобрать в деталях на любом уровне глубины:
реальный найденный баг, архитектурное решение с ценой ошибки, защита
линии от зависания на реальном железе.

## За что я отвечаю

За то, что линия не встанет и не пропустит брак. В каждом кейсе моё —
архитектурное решение (почему `REJECT`, а не `MANUAL_REVIEW`; почему
процесс не падает; почему защёлку снимает только оператор), критерий
приёмки числом и разбор причины бага. Реализация модулей написана с
Claude Code по этим требованиям — инструмент не скрываю, в README
каждого кейса граница проведена явно. Проверка — не текст в README, а
разбор вживую.

## Кейсы

| Кейс | О чём | Что показывает | Число |
|---|---|---|---|
| [`case-1-jetson-plc-watchdog/`](case-1-jetson-plc-watchdog/) | Watchdog вокруг CV-инференса на реальном Jetson, с измеренным запасом по времени | Инженерная дисциплина: что происходит, когда реальное железо не отвечает вовремя, а не просто «код работает» | p99 67.7 мс при таймауте 350 мс → запас 282 мс, измерено на плате |
| [`case-2-drift-detection-bug/`](case-2-drift-detection-bug/) | Реальный баг на железе: камера молча не открыта, 300 одинаковых ошибок вместо одной содержательной | Умение найти причину, а не симптом — и почему сообщение об ошибке само по себе часть инженерной работы | 300 одинаковых ошибок → одна содержательная; баг невидим на симуляторе в принципе |
| [`case-3-pid-antiwindup/`](case-3-pid-antiwindup/) | PID-регулятор с антивиндапом и контринтуитивным фактом про D-составляющую | Доменное суждение, которое невозможно сгенерировать не понимая теорию управления | интеграл после 1000 тактов в насыщении: <100 с антивиндапом, >50 000 без |

## Проверить самому

```bash
pip install pytest
python -m pytest case-1-jetson-plc-watchdog   # возврат управления через timeout_s, защёлка, зависшие потоки
python -m pytest case-3-pid-antiwindup        # антивиндап (1000 тактов в насыщении), производная по измерению, факт про D
```

Тесты закрепляют числами то, что в README каждого кейса заявлено
словами: интеграл без антивиндапа уходит за 50000, с ним остаётся <100;
при зависшем инференсе `run()` возвращается через таймаут, а не через
длительность инференса; на объекте первого порядка D увеличивает
перерегулирование. Кейс 2 — разбор бага, кода для тестирования в нём
нет намеренно. CI гоняет это на Python 3.10 (JetPack 6) и 3.12.
