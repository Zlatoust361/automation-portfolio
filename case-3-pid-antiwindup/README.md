# Кейс 3: PID-регулятор с антивиндапом — и факт, который противоречит интуиции

## Задача

PID-регулятор тока/напряжения сварочного источника. Чистый Python
(только stdlib) — регулятор не знает ни про Modbus, ни про БД, ни про
безопасность, и тем же классом управляется позже реальный источник
питания без единой правки логики.

Две вещи отличают рабочий промышленный PID от учебного — обе сделаны
намеренно, не по умолчанию библиотеки.

## 1. Антивиндап — и реальная цена его отсутствия

Когда выход регулятора упирается в физический предел (у сварочного
источника — диапазон задания тока), интегральная составляющая без
защиты продолжает расти и накапливает «долг», который потом
отрабатывается перерегулированием — для сварки это бросок тока сверх
нормы, то есть прожог детали.

```python
# Антивиндап: интегрируем, только если это не загоняет выход глубже
# в насыщение. Проверяем на пробном значении, не трогая состояние.
candidate_integral = state.integral + error * dt
unclamped = proportional + config.ki * candidate_integral + derivative
clamped = self._clamp(unclamped)

pushing_further = (
    (unclamped > config.max_output and error > 0)
    or (unclamped < config.min_output and error < 0)
)
if not pushing_further:
    state.integral = candidate_integral   # интегратор копится
    output = clamped
else:
    # Интеграл замораживаем и пересчитываем выход на старом значении.
    frozen = proportional + config.ki * state.integral + derivative
    output = self._clamp(frozen)
```

Интегратор замораживается именно тогда, когда выход в насыщении **и**
ошибка продолжает толкать его дальше в ту же сторону — не всегда, когда
выход в насыщении: если ошибка сменила знак, интегратору нужно дать
двигаться обратно.

**Измеренная цена отсутствия защиты:** после 1000 тактов в насыщении
интеграл с антивиндапом остаётся <100 — без него он уходит за 50000.
Разница на три порядка, не на проценты.

## 2. Производная по измерению, а не по ошибке

При скачке уставки производная ошибки даёт мгновенный выброс (derivative
kick) — для источника питания это бросок тока в момент команды, не в
момент реального изменения процесса. Производная берётся от измеренного
значения процесса, поэтому смена уставки сама по себе на неё не влияет.

## Факт, который противоречит интуиции

Расхожее правило «D уменьшает перерегулирование» **не выполняется** на
апериодическом объекте первого порядка (характерном для теплового/
токового процесса сварки): D замедляет подъём к уставке, из-за чего
ошибка дольше остаётся положительной, и интеграл за это время копит
больше, чем копил бы без D-составляющей — то есть перерегулирование
может оказаться **больше**, не меньше. Это не опечатка и не баг теста —
это свойство именно этого класса объектов, подтверждённое прогоном, а не
вычитанное из общего учебника про PID без оговорки на тип объекта.

Это и есть разница между «знаю, что такое PID» и «понимаю, когда
стандартная интуиция про PID не работает» — второе нельзя получить
простым чтением документации регулятора, только пониманием физики
объекта управления.
