# Кейс 1: watchdog вокруг CV-инференса на реальном Jetson

## Задача

Линия с конвейером: ПЛК по Modbus, камера на Jetson Orin Nano, модель
детекции дефектов в CV-пайплайне. На симуляторе инференс всегда
возвращает ответ. На реальном железе — нет: модель может уйти в своп при
нехватке unified memory, TensorRT-контекст может подвиснуть на GPU, USB-
камера — отвалиться посреди чтения кадра. Без защиты от этого конвейер
либо зависает с деталью в зоне контроля (оператор смотрит на
неподвижную линию), либо хуже — продолжает ехать, и непроверенная
деталь уезжает как годная.

## Архитектурное решение

- Вызов инференса оборачивается таймаутом (`asyncio.wait_for`); по
  истечении — деталь получает `REJECT`, не `MANUAL_REVIEW`: модель в
  этом случае вообще не успела посмотреть на деталь, значит не может
  "засомневаться" — непроверенное дешевле отбраковать, чем пропустить.
- Процесс при срабатывании watchdog **не падает** — упавший управляющий
  процесс на линии хуже остановленной линии, потому что после него
  некому выключить привод.
- `asyncio.wait_for` отменяет задачу на уровне event loop, но синхронный
  инференс, запущенный через `asyncio.to_thread`, физически продолжает
  крутиться в потоке — у CPython нет способа убить поток извне. Это не
  баг, а ограничение платформы, с которым архитектура спроектированно
  живёт: зависшие вызовы считаются отдельно (`abandoned`), пул потоков
  ограничен, и когда все заняты зависшими вызовами — следующий вызов не
  встаёт в очередь, а сразу отвечает таймаутом, не маскируя причину под
  "просто медленно".
- Защёлка держит линию остановленной, пока зависший вызов не разберут
  вручную — не автоматический сброс.

Код — [`safety_watchdog.py`](safety_watchdog.py), полный модуль, не
вырезка: он самодостаточен и не тянет остальной репозиторий.

## Критерий приёмки

Watchdog принимается не по факту «не падает», а по измеренному запасу
времени между реальной латентностью инференса и таймаутом безопасного
останова — иначе защита формально есть, а реального запаса может не
быть.

## Реальный замер на железе

Бенчмарк 200 итераций на Jetson Orin Nano, реальная конфигурация линии:

```
латентность: среднее 48.0 мс, p95 66.5 мс, p99 67.73 мс
watchdog-таймаут: 350 мс → запас 282 мс
память: 41% (3131/7620 МБ)
режим питания: 15W 0 (максимальный для этой платы)
```

282 мс запаса на p99 — не круглое число «для вида», а то, что получилось
на реальном прогоне и было явно задокументировано, а не предположено.
